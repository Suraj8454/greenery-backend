# Cityscape Admin UI Setup

This update modernizes the EJS admin login, dashboard, products, product form, orders, users, pages, page editor, and settings screens. Existing admin URLs, form actions, database/controller logic, and password update API have been preserved.

## Setup on Windows

1. Extract this ZIP into your project folder (keep a backup of your current folder first).
2. Copy your own `.env` file into the project root. The ZIP intentionally does not include the real `.env` because it contains credentials. Use `.env.example` as a reference and keep your existing database values and JWT secret.
3. Open a terminal in the backend folder and run:

   ```bash
   npm install
   npm run build:css
   ```

4. Start the backend in one terminal:

   ```bash
   npm run dev
   ```

5. Open `http://localhost:5000/admin/login` (or the port configured in your `.env`).

For live CSS rebuilding while changing UI, use a second terminal and run `npm run watch:css` instead of `npm run build:css`.

## Important

- `public/css/tailwind.css` is generated by the build command; do not manually edit it.
- The shared EJS layout is wired through `controllers/adminController.js` so all admin pages use the same sidebar, header, styles, and responsive mobile menu.
- Do not commit `.env` or share it publicly.


## Enhanced CMS, fulfilment and editorial tools

- **Admin → Homepage personal tabs** (`/admin/sections`): Featured In, Trust Badges, How It Works, Why Choose Us, Plant Story, Bulk Orders, and Headings & Subheadings. Existing storefront sections retain the original homepage sequence. Each section's heading, eyebrow, description, image, icon, colours, CTA, visibility and individual cards/logos/features can be edited in the visual item editor. Hero slides remain in Admin → Hero slider.
- **Admin → Orders**: compact table view. Open View details to see customer contact/address, ordered item images and quantities, subtotal/shipping/discount/total, payment state, timeline and expected delivery date. Saving a status/date adds a timeline event. The customer order history also displays ETA and timeline.
- **Invoice PDF**: a branded A4 invoice with a deep-green header, company identity, order ID/date/status, separate customer and delivery columns, payment/promo summary, line-item table with quantity/unit price/right-aligned amount, totals panel, and page numbering for long orders.
- **Admin → Contact messages**: change status to New / Contacted / Resolved, add a private follow-up note, open WhatsApp when a phone number was supplied, or delete spam.
- **Admin → Blog posts**: manage featured image, author, category, tags, hashtags, draft/published status, publish date, reading time, SEO title/description, focus keyword and canonical URL. Published blog pages update document title, description and Open Graph metadata.
- Database setup automatically creates missing columns and the `home_sections` and `order_timeline` tables without dropping existing product/order data. Back up MySQL before first startup.

## Recommended local test order

1. Create `.env` from `.env.example` and set a local MySQL account that has permission to create/use the configured database.
2. Run `npm install`, then `npm run build:css`, then `npm run dev` in the backend.
3. In the frontend, create `.env` from `.env.example`, run `npm install`, then `npm run dev`.
4. Sign in at `/admin/login` using the initial credentials printed in the backend terminal. Change the default password before deployment.
5. Test product create/edit/delete and image upload; then each homepage section, its card JSON and visibility/order; blog draft/publish/SEO; contact submission and Contacted status; COD checkout; order detail; ETA/timeline update; PDF invoice download; promo validation and discount; testimonials and store settings.

**Security note:** the default local admin account is only for initial development. Change its password and configure a strong `JWT_SECRET` before deploying. Never deploy the `.env` file or commit production credentials.
